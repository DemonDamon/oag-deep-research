# OAG 深度调研协议

## 1. 目标与边界

本协议规定如何把一个开放式研究问题转换为可复用的研究资产。它使用**轻量本体**约束检索和综合，而不尝试构建覆盖所有概念的重型知识图谱。每项资产应能回答以下问题：结论是什么、适用于什么范围、依赖哪些对象和关系、由什么证据支持、哪些部分只是推断。

> **定义。** 在本项目中，OAG 指 Ontology Augmented Generation：生成过程不仅以检索到的文本为上下文，还以受控的对象、关系、逻辑和行动边界为语义锚点。[1]

| 层次 | 产物 | 作用 |
|---|---|---|
| 问题层 | 研究简报 | 声明问题、范围、假设与读者 |
| 语义层 | 轻量本体 | 描述对象、属性、关系、时间与约束 |
| 证据层 | 来源登记与主张账本 | 让事实与引用可定位、可审查 |
| 推理层 | 推断记录 | 展示前提、规则、反例和限制 |
| 决策层 | 行动边界 | 明确仅供分析的建议与需要授权的行为 |

## 2. 最小本体规范

为每个主题定义 `entity_id`、`type`、`name`、`properties` 和 `temporal_scope`。关系必须使用方向明确的名称，如 `organization:publishes:document`，并尽可能标记有效时间与证据来源。关系的存在、方向和适用条件都应被单独验证。

| 元素 | 最小字段 | 示例 |
|---|---|---|
| 对象 | ID、类型、名称 | `entity:palantir`，组织，Palantir |
| 属性 | 名称、值、时间、来源 | `revenue`，数值，FY2025，年报 |
| 关系 | 起点、谓词、终点、时间 | `entity:a — publishes → entity:b` |
| 约束 | 条件、范围、例外 | 仅适用于某区域或版本 |
| 主张 | 文本、状态、证据 | `claim:...`，`supported`，`src:...` |

## 3. 来源与证据优先级

关键结论首先应由一手资料、原始数据、监管/政府出版物、正式技术文档或同行评审论文支持。二手媒体与行业解读可以解释背景，但应在来源账本中单独标识其地位和潜在偏差。检索页摘要、社交媒体片段和无法访问的引用只能作为发现线索。

| 证据等级 | 典型来源 | 适用方式 |
|---|---|---|
| 高 | 一手资料、原始数据、正式文档、同行评审 | 支撑关键事实或正式定义 |
| 中 | 可信行业研究、专家分析、经过编辑审查的媒体 | 补充比较和上下文 |
| 低 | 搜索摘要、无法核验转载、主观看法 | 提出假设或查询，不支撑结论 |

## 4. 推断规则

推断不是事实的同义词。只有在前提明确、前提被证据支持且推理规则可解释时，才可生成 `inferred` 主张。对于事实冲突、样本不足、时间过期或概念不一致的情况，应维持 `contested` 或 `unverified` 状态。

推断记录至少包括：引用的主张 ID、采用的规则、适用范围、可能反例、置信度，以及把推断升级为支持性结论所需的下一条证据。

## 5. 行动边界

任何面向实际系统、资金、医疗、法律、招聘、访问权限或个人数据的建议都必须与执行分离。报告可给出可研究的选项和不确定性，但不能将不完整的研究证据包装为自动执行指令。需要权限、合规审查或人工决策的步骤必须明确标记。

## 6. 报告验收标准

完成报告前，审查者应确认：研究问题未被悄然扩大；关键结论链接到主张 ID；主张链接到可定位来源；推断、争议和未知项没有被混同；本体没有包含不必要的无证据关系；行动边界与来源限制均被保留。
