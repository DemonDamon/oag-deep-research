# Prototype 模块摘要

## 目的

`prototype/` 是 Orion 决策本体与 OAG 的纯静态浏览器原型。它通过四个行业场景展示岗位任务、业务对象、关系图、确定性图检索、证据链、Action 提案、审批与四权分离。它不是生产系统，不连接外部身份、数据库或写回接口。

## 主要文件

| 文件 | 职责 |
|---|---|
| `prototype/index.html` | 页面入口与 ECharts、场景、引擎、UX、应用脚本加载顺序 |
| `prototype/js/app.js` | 全部页面渲染、路由状态、决策闭环、图谱、OAG、模拟、提案与审批交互 |
| `prototype/js/engine.js` | 实体识别、关系意图、两跳遍历、确定性回答与证据对象生成 |
| `prototype/js/ux.js` | 四个场景的岗位、任务、Action、风险、审批人、前置校验、回滚和 RAG 对照文案 |
| `prototype/js/scenes-inline.js` | 浏览器内嵌的类型、对象、属性和关系数据 |
| `prototype/css/app.css` | 视觉变量、工作台布局、决策闭环、工具轨迹、Action 三栏与响应式样式 |

## 当前产品结构

应用包含本体工作台、OAG 问答和 RAG/OAG 对照三个产品视图。首页从当前岗位事件进入“事件—对象—推演—审批—执行/记忆”五阶段闭环。Action 工作台同时展示对象上下文、保持现状/采用方案比较以及执行边界；只有浏览器内模拟完成后，才可生成提案。OAG 回答展示查询对象、图关系计算、组织证据和申请 Action 的工具轨迹。

## 数据与状态流

场景数据由 `scenes-inline.js` 加载并交给 `OagScene` 建立内存索引。问题经过实体与关系意图解析后执行最多两跳遍历，回答和证据保存在 `state.lastAnswer`。本地模拟状态保存在 `state.simulations`，提案和审批保存在 `state.proposals`；刷新页面后这些业务状态不会持久化。

## 安全边界

所有“模拟”“审批”和“写回”都是前端演示状态。未来若进入真实实施，必须在外部服务层补齐身份认证、对象级授权、函数与 Action 独立授权、审批策略、幂等、审计、回滚和源系统连接。前端按钮不可直接等同于生产 Action。

## 维护触发条件
