## 文章的核心叙事

文章以“企业行动手册”比喻本体，强调 Agent 不应直接面对混乱的源系统表结构，而应在对象、关系、规则、函数、行动与记忆共同形成的业务语义层上工作。[1] 文章进一步用航空维修与航班调整示例描述一个闭环：业务事件触发任务，Agent 装配相关对象与关系，比较多个候选方案，调用模型评估影响，由人员选择方案后提交受控行动申请，再由平台校验权限、对象状态和写回条件。[1]

这是一种有价值的产品解释框架，但不能据此断言任一产品已经“根除幻觉”。更安全的工程表述是：本体、确定性函数、来源证据、权限与 Action 审批可以**收窄模型的自由度并提高可审计性**；输出是否正确仍取决于数据质量、模型行为、规则覆盖、工具实现和运行治理。

## 图示中可迁移的产品模式

| 图示模式 | 可见信息 | 对 `prototype/` 的迁移 |
|---|---|---|
| 分步定义对象类型 | 数据源、元数据、属性、关系/链接、Actions 分阶段配置 | 对象类型页增加五步建模导航，明确本体不是字段列表 |
| 图谱与属性/模拟面板同屏 | 画布保留对象关系，侧栏配置参数并运行场景 | Action 页采用对象上下文、情景推演、执行边界三栏工作台 |
| Action 独立于普通按钮 | 动作有目标对象、参数、提交条件、函数和写回范围 | Action 必须显示前置校验、审批人、幂等键、回滚和写回系统 |
| 多方案比较 | 保持现状与候选方案在执行前进行模拟 | 提案按钮在本地模拟完成前保持禁用 |
| Agent 工具分级 | 查询对象、计算、调用函数和应用 Action 分开呈现 | OAG 回答增加工具轨迹，并把只读能力与写入申请视觉分离 |
| 决策形成记忆 | 方案、执行和结果进入下一轮改进 | 首页用事件—对象—推演—审批—执行/记忆五阶段闭环表达 |

## 已实施的 prototype 优化

本轮没有复制文章图片或界面，而是将其中的交互原则转化为原创实现：

1. 首页从“指标看板”改为岗位决策入口，突出当前业务事件、锚定对象和能力边界。
2. 新增五阶段决策闭环，明确当前步骤以及锁定步骤。
3. Action 页新增对象上下文、保持现状/采用方案比较、权衡、前置校验、审批人、幂等键和回滚说明。
4. 只有完成本地情景模拟后，才能生成 Action 提案；模拟与提案均不会调用外部系统。
5. OAG 回答新增查询对象、图计算、组织证据、申请 Action 四级工具轨迹。
6. 对象类型页增加分步建模导航、属性/关系/Action 统计和业务对象示例。

## 使用边界

文章中的产品截图和厂商叙事适合作为交互启发，不应作为安全性、准确率、成本、性能或企业实施效果的证明。原型中的“模拟”“审批”和“写回”均为浏览器内演示状态；任何生产落地都必须另行实现身份认证、对象级授权、审批策略、幂等、审计、回滚与源系统连接。
