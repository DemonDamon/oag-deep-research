# 用户资料阅读卡：GraphRAG 厂商案例与可信主张评估

## SRC-2026-08-07：Graphwise GraphRAG “Trust Layer”

Graphwise 的官方博客将其 GraphRAG 描述为结合知识图谱语义推理、图搜索、向量搜索和全文搜索的生成式 AI 引擎，并主张它通过可解释回答、来源引文、审计追踪、认证授权和输入/输出护栏为受监管企业提供“信任层”。页面列出 Keycloak、GraphDB、Elastic/OpenSearch、多轮对话、SSE API 等产品能力。[1]

这类材料适合作为**供应商能力声明和评估假设来源**，而不是作为效果已被独立证明的证据。页面提到金融监管、医疗、ESG 等高风险应用场景，但未提供可独立复核的基准数据、样本量、失败率、对照组或评测协议。因此本卡将其归入 `06`，而非把产品叙事写入 `03` 的检索机制结论。

## 评估转换表

| 厂商声明 | 可检验问题 | 需要的证据 |
|---|---|---|
| 混合图/向量/全文检索 | 对特定任务是否优于稠密检索或关键词基线？ | 固定语料、查询集、检索召回/精确率、延迟与成本 |
| 语义推理与多跳问答 | 推理路径是否正确且可重放？ | 明确图模式、路径记录、金标准、错误分类 |
| 来源引文与可审计性 | 引文是否精确支持回答？ | 引文精确率、覆盖率、失效链接率和人工复核 |
| 输入/输出护栏 | 护栏对越权、提示注入、敏感泄露的效果如何？ | 攻击集、拒绝/误拒率、绕过案例、审计日志 |
| 监管适用性 | 是否满足目标行业的实际治理要求？ | 适用法规映射、控制项、责任人、数据留存与外部审计 |

> 该表可被 Near 的评估任务复用：先将产品功能声明转为可反驳问题，再要求实验、日志、对照和来源支撑，避免以“可信”作为不可验证标签。

## 与其他方向的关系

`03` 可引用本卡说明 GraphRAG 的产品机制候选；`05` 可引用其认证、护栏和审计主张；但关于任何“降低幻觉”“合规可用”“生产成熟”的结论，必须在本方向以独立证据单独评估。
