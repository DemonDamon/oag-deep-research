# Semantica 的 AgenticX 研究裁决

## 决策

| 项目 | 结论 |
|---|---|
| 最终裁决 | **`DO_NOT_ADOPT`（当前不采纳）** |
| 立即动作 | 归档版本锁定研究，不进入 AgenticX 生产实现队列。 |
| 后续动作 | 仅当出现明确的可审计决策工作流、已批准的隔离实验和固定数据契约时，重新评估 G-003。 |

作出该裁决的原因如下。G-001 表明 AgenticX 已在检查范围内具备持久 MCP 客户端、三类传输和默认拒绝的工具政策；Semantica 贡献的是服务端工具面，而不是应替换的客户端能力。[E-010] [E-011] [E-012] G-002 表明 Semantica 默认 `ContextGraph` 为内存实现，静态证据不能证明其优于 AgenticX 现有 Graphiti/Kuzu 图记忆。[E-004] [E-014] G-003 的决策/溯源机制值得作为研究参考，但缺少经过验证的真实工作流、运行验证、授权模型和存储兼容性，优先级只能是 P2。[E-002] [E-003] [E-005]

本轮明确不做三类工作：不将 Semantica MCP 客户端、`ContextGraph` 或动态 `PluginRegistry` 复制到 AgenticX；不将 Semantica MCP 的写图/导出工具直接暴露给 Near 用户或 Agent；不安装 `semantica[all]`、不运行上游服务、不启用外部数据库，也不使用生产凭据。

## 1. 背景与研究边界

本研究按固定源码提交 `94d0c3dc07109fb4e6df3027dbd571eeefc45d52` 审阅 `semantica-agi/semantica`，并将其与固定 AgenticX 基线 `de771f7160317fc75a39fa9474480e8e7ea5850b` 的 MCP、工具政策、上下文编译和 Graphiti/Kuzu 记忆图实现对照。范围只包括研究与采纳决策：没有修改 AgenticX 生产代码，也未对 Semantica 做安装、运行、压测或安全认证。

## 2. 可复用的上游知识

Semantica 最值得复用的是架构原则，而不是可以直接搬运的完整模块。决策记录应把决策者、推理、置信度、相关实体、源文档、有效期和政策版本写成显式对象，而不要散落在模型输出文本中。[E-003] 图上下文应区分实体关系与时间有效性，并对时间格式异常给出确定行为。[E-004] 当溯源是可选依赖时，数据契约必须明确其启用条件；“支持 provenance”不等于每条决策都会自动产生可审核谱系。[E-003] 最后，MCP 是协议暴露层而不是权限系统；工具读写分级、调用方身份、政策、审批和审计应由 AgenticX/企业网关控制。[E-002] [E-012]

## 3. AgenticX 能力与无缺口/P2 结论

| 发现 | 当前证据 | 决策 |
|---|---|---|
| MCP 传输/会话生命周期 | AgenticX 有持久会话、stdio/HTTP/SSE、工具发现和可恢复错误重试。 | 无缺口；不采纳 Semantica 作为客户端。 |
| 工具授权 | AgenticX 政策栈支持拒绝优先、默认拒绝、路径/计划/命令/类别政策。 | 无缺口；Semantica MCP 服务必须置于该边界之后。 |
| 图记忆 | AgenticX 有 Graphiti/Kuzu episode memory、初始化超时和恢复逻辑。 | 无缺口；不替换为默认内存 `ContextGraph`。 |
| 决策/溯源语义 | Semantica 有可检查的决策、政策、异常、批准链与可选溯源代码。 | P2；仅作为未来研究主题。 |
| 动态插件加载 | Semantica 有动态 Python 插件注册；AgenticX 已有技能包方向。 | 无缺口；避免扩大执行面。 |

## 4. 当前不采纳的原因：价值、成本与回归风险

Semantica 是宽平台形态而不是最小库。基础依赖已经包含机器学习、图、文档、媒体和向量组件，另有 LLM、图后端、向量后端、云、监控、Explorer 和 SHACL 等可选组。[E-001] 直接采纳会使 AgenticX 同时承担两个上下文/图体系、多个数据生命周期以及 MCP 服务工具写入风险。

本轮没有真实业务用例、系统接口、数据分级、授权传播或运行验证。因而潜在价值不能超过 P2，成本和回归风险也无法被合理化。当前合理做法是保留版本锁定的研究资产与设计原则，而不是立即引入新的运行时。

## 5. 明确排除：不进入实现队列

本轮不建立 `.cursor/plans/`，不创建代码任务，不拷贝上游模块，不引入新依赖，不配置 Semantica MCP，不迁移图记忆，不连接企业系统，也不依据 DeepWiki 的旧索引做功能承诺。若未来要采用相关语义，优先将本仓库已有的主张账本、来源、对象、关系和行动边界作为独立数据契约，而不是先绑定某个上游运行时。

## 6. 再评估触发条件

只有同时满足下列条件，才应重新触发一次代码深度调研：提出者给出具体岗位和决策闭环，例如“维修工单例外批准”；明确需存储哪些决策字段、保存多久、谁可读写、何时允许写回；能在无敏感合成数据上定义成功/失败样本和审批边界；允许在隔离环境针对固定上游 SHA 运行最小只读实验；并确认 AgenticX 图记忆和 Semantica 图/溯源组件的职责边界，而非将二者都笼统称为“长期记忆”。

## 7. 下一步规划调整

将 Semantica 从“拟集成组件”下调为“版本锁定的设计参考”。下一轮优先工作应从现有 OAG 研究资产中选定一个真实决策闭环，先写清对象、关系、来源、证据、政策、批准和 Action 的数据契约；只有该契约证明 AgenticX 当前确实无法满足可审计决策需求时，才重新评估 G-003。
