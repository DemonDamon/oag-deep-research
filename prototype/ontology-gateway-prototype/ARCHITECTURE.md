# 企业本体与能力网关参考架构

## 1. 产品边界

本产品由企业端的**本体与能力网关**和用户端的 **AgenticX / Near 终端智能体**组成。企业端保存权威对象类型、跨系统身份映射、能力目录、策略、Action 定义和审计记录；终端仅持有当前会话所需的对象上下文、授权信息和可撤销缓存。

> 本体层不是单一图数据库，也不是另一个自由对话智能体。它是由统一语义、对象查询、身份解析、能力目录、Action 网关、策略和审计共同组成的企业服务层。

## 2. 两种可行部署方式

| 方案 | 运行形态 | 主要取舍 | 成本特征 | 建设复杂度 |
|---|---|---|---|---|
| 模块化全栈服务 | React 控制台、无状态 Node API、共享关系数据库；领域模块在同一部署单元内保持清晰边界 | 交付快、事务简单、适合验证对象与 Action 闭环；独立扩缩容能力有限 | 低，可从按需自动扩缩开始 | 中 |
| 事件驱动领域服务 | 网关、Ontology、Connector、Identity、Action、Policy、Audit 分别部署，使用事件总线与独立存储 | 可按领域扩缩和隔离故障；分布式一致性、可观测性和运维成本显著增加 | 高，需要独立网关、队列、数据库与运行平台 | 高 |

本原型采用第一种方式，但代码与数据模型按照第二种方式划分模块。后续可在不改变前端对象、能力和 Action 契约的情况下，逐步把高负载或高风险模块拆分为独立服务。

## 3. 六层逻辑架构

| 层级 | 当前原型职责 | 生产演进方向 |
|---|---|---|
| 数据接入 | 保存连接器、源系统标识和同步状态 | 独立 Connector Runtime、事件消费与数据契约校验 |
| 语义与身份 | 管理对象类型、对象、关系和异构 ID 映射 | 领域本体服务、Schema Registry 和统一 Identity Resolver |
| 查询与证据 | 对统一对象、关系和来源证据提供读模型 | 图存储、搜索与向量索引的混合查询层 |
| 逻辑与 Action | 模拟、提案、审批、回滚计划和执行状态机 | 独立 Action Orchestrator、幂等执行器和补偿流程 |
| 安全与治理 | 四角色权限矩阵、策略、白名单和审计事件 | 外部策略引擎、对象级授权、不可篡改审计存储 |
| Agent 接入 | 提供 MCP/API 网关能力清单和调用约束 | 身份委托、速率限制、租户隔离、协议适配与可观测链路 |

## 4. 领域服务边界

| 模块 | 权威职责 | 不负责的事项 |
|---|---|---|
| Ontology | 类型、属性、关系、约束、函数、Action 定义及版本 | 连接源系统和执行写回 |
| Object Graph | 企业对象、关系、证据和状态投影 | 修改源系统事实 |
| Identity | CRM `customer_id`、ERP `buyer_code` 等异构 ID 到统一对象 ID 的映射 | 业务规则判断 |
| Connector | 系统注册、健康度、凭据引用和能力声明 | 跨系统决策 |
| Capability Catalog | Query、Function、Proposal、Action、Event 五类机器可读契约 | 直接持有系统凭据 |
| Decision | 方案、模拟结果、跨系统影响和回滚计划 | 绕过审批执行写回 |
| Action | 提案状态机、幂等键、审批和执行结果 | 无授权的自由调用 |
| Governance | 角色、策略、白名单和审计 | 替代源系统自己的安全控制 |
| Gateway | 面向 AgenticX / Near 的能力发现和受控调用入口 | 暴露底层数据库连接 |

## 5. 一致性与高可用设计

API 服务保持无状态，所有业务状态进入共享数据库。每个写操作携带幂等键和期望版本号；Action、审批和审计在同一事务边界内写入。跨系统执行采用“提案—审批—执行—补偿”的状态机，不对分布式源系统承诺单库事务。

生产级部署应在入口层进行健康检查、限流和租户路由；数据库使用托管高可用集群；Connector Runtime 与 Action Executor 使用队列削峰；审计事件采用追加写；对象查询使用可重建读模型。实时体验可以通过事件订阅或短轮询实现，但不能把关键状态只放在单个进程内存中。

## 6. 权限与身份模型

固定角色为：**业务员工、主管、本体建设者、开发/治理人员**。权限拆分为读取、提案、审批、执行四个动作，不把页面可见性等同于数据权限。终端调用需同时携带用户身份、调用方身份、租户、当前对象、会话目的和请求的能力范围。

## 7. MCP/API 网关契约

网关只允许 **AgenticX** 和 **Near 终端智能体**作为受信调用方类型。原型提供机器可读清单，包含协议版本、对象查询能力、Action 能力、输入/输出 Schema、风险等级、所需角色、是否只读以及审批要求。真实 MCP Server 或外部 REST 网关属于后续部署适配器，不在浏览器中直接持有企业凭据。

## 8. 关键业务闭环

```text
异常事件 → 统一对象定位 → 跨系统证据查询 → OAG 解释
        → 方案比较与模拟 → Action 提案 → 人工审批
        → 受控执行/补偿 → 状态回流 → 审计与业务记忆
```

本原型以该闭环作为验收主线。所有高风险操作必须从对象上下文进入，先模拟、后提案、再审批；界面不提供绕过治理的直接写回入口。
