# 前端工作区模块摘要

## 信息架构

前端采用持久侧边栏的企业控制台结构，十个工作区按运营、语义、决策、治理和接入分层。全局角色切换器固定支持 **业务员工、主管、本体建设者、开发/治理人员**，并把当前视角持久化到浏览器本地存储；该切换器只用于演示，不替代服务端授权。

| 体验主线 | 涉及工作区 | 验收目标 |
|---|---|---|
| 发现问题 | 运营首页 | 从异常进入统一对象或决策上下文 |
| 建立语义 | 对象与关系、本体工作室、身份映射 | 看见统一 ID、关系、属性、来源和版本 |
| 形成判断 | OAG 智能助手、决策工作台 | 检查工具轨迹、确定性规则、引用和方案影响 |
| 受控写回 | 决策工作台、审批与治理 | 先模拟、再提案、后审批，并显示回滚边界 |
| Agent 接入 | 连接器、MCP/API 网关、角色权限 | 发现机器可读能力及调用方、风险和授权要求 |

## 设计系统

视觉以深青背景表示企业语义与运行稳定性，以燃橙强调风险、决策和受控写操作。`glass-panel`、`signal-grid`、`ambient-orb`、状态徽标和能力徽标构成可复用基础。布局在大屏展示高密度三栏关系和决策视图，在窄屏收起侧边栏并让卡片单列排列。

## 关键交互约束

OAG 聊天返回的是可检查答案，而不是自由写回入口。决策工作台只有在模拟完成后才能生成提案预览；真实提交要求登录。Gateway 页面明确受信调用方仅为 **AgenticX** 与 **Near 终端智能体**，并把 `action.execute` 标注为高风险且需要审批。

## 后续建议

下一阶段应增加真实对象筛选、图关系缩放与布局、Schema 编辑和版本差异、审批证据抽屉、网关调用测试台、键盘命令面板与更完整的错误状态。接入生产数据前，所有页面都必须处理字段级脱敏、对象级授权和数据来源不可用状态。
